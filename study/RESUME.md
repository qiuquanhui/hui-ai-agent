# RESUME.md —— 把这个项目写进简历的正确姿势

> 本文教你两件事：① 简历条目怎么写才"值钱"；② 针对 hui-ai-agent 这个项目，直接给出 14 条要素齐全、可直接抄改的条目。
> 配套的面试自检题见 [INTERVIEW.md](./INTERVIEW.md)——那 30 道题就是照着本文的条目来问的。

---

## 一、简历条目的万能公式

> **为了达到什么目的（或解决什么问题），使用了什么技术，做了什么，达到了什么效果。**

这个公式其实是面试官最爱的 STAR 法则（Situation-Task-Action-Result）的中文压缩版，四段拆开看：

| 段 | 回答的问题 | 面试官心里在想 |
| --- | --- | --- |
| **目的 / 问题** | 你为什么要做这件事？ | "他是带着问题干活的，不是堆技术" |
| **技术** | 你选了什么方案？ | "他知道自己在用什么，不是抄的" |
| **做了什么** | 具体动作是什么？ | "真的动手做过，有细节" |
| **效果** | 带来了什么改变？ | "做事有闭环，能衡量结果" |

**效果尽量量化**：说"提升了检索准确率"不如说"违规请求在到达模型前被拦截，零 token 浪费"；说"优化了部署"不如说"镜像从 1GB+ 瘦身到几百 MB，冷启动明显变快"。没有精确数字时，用**可验证的定性描述**（"跨重启仍能记住对话"、"打字机效果还原"）也比空话强。

⚠️ **公式是骨架，不是句式模板**：四要素（为什么/用什么/做什么/什么效果）条条都要有，但**句式必须换着来**——有的从痛点说起，有的直接亮动作，有的拿结果开头。十四条全用"为了……，使用了……"一个模子刻出来，面试官三十秒就能闻出"这是 AI 写的"。

## 二、写之前，先想清楚面试官怎么读简历

1. 面试官平均在一条项目经历上停留 **10~20 秒**——公式四段里"目的"和"效果"最先被看到，必须具体；
2. 每一条简历条目，都是你**主动递给面试官的提问邀请**——写"自定义 Advisor 责任链"，就是邀请他问责任链；写不熟的东西，等于给自己挖坑；
3. 一个项目写 **8~15 条**为宜：太多像流水账，太少显得没干活；按"含金量从高到低"排序（手写 Agent、RAG 这种放前面）；
4. 所有条目必须**经得起三层追问**：是什么 → 怎么实现的 → 为什么这么实现/换你会怎么做。经不起就别写（对照 [INTERVIEW.md](./INTERVIEW.md) 自检）。

## 三、本项目的简历条目（14 条，要素齐全、句式刻意不重样）

> 括号里的【标签】对应学习手册 STUDY.md 的阶段和 INTERVIEW.md 的题号分组，方便你复习和备考。
> 留意每条的开头方式各不相同：有的从痛点切入、有的直接亮动作、有的拿结果说话——这正是上一节那句 ⚠️ 的示范。

1. 【骨架与文档·阶段1】项目基于 Spring Boot 3.4.4 + JDK 21 + Maven 搭建，接入 knife4j（OpenAPI3）在线接口文档并支持网页端调试；新增接口先在文档页自测、再交付前端，联调来回明显减少。

2. 【选型调研·阶段2】动手阶段先后用 Hutool 裸 HTTP、灵积官方 SDK、Spring AI Alibaba、LangChain4j、Ollama 五种方式接通通义千问，横向对比封装程度与代码侵入性后确定 Spring AI 为主力框架——也借此吃透了从"HTTP + JSON 协议本质"到框架自动装配的整条链路。

3. 【提示词工程·阶段3】基于 ChatClient 的 defaultSystem 设计"身份—开场—分类提问—引导细节"四段式系统提示词，多轮对话中"恋爱专家"人设稳定，追问方向不再漂移。

4. 【Advisor 责任链·阶段4】日志、鉴权、内容安全这类通用能力没有揉进业务代码，而是自定义 CallAroundAdvisor / StreamAroundAdvisor 责任链统一处理（观察型日志、Re-Read 增强、权限校验、违禁词拦截四类）；用 getOrder 精确控制执行顺序，让违规请求在写入会话记忆之前就被拦下——拦截即不调用模型，token 一分不浪费。

5. 【对话记忆·阶段5】大模型天生"金鱼记忆"，多轮对话靠策略模式补齐：ChatMemory 接口下实现内存、Kryo 文件、MySQL 三种存储，MessageChatMemoryAdvisor 在每次调用前注入最近 N 条历史，按 chatId 隔离会话、跨重启不忘。

6. 【结构化输出·阶段3】AI 的回答要交给程序用，就不能靠正则抠文本：用 entity() 结构化输出 + victools JSON Schema，让模型按预定义 record 填 JSON、自动反序列化成 Java 对象，对接可靠性比解析自由文本高得多。

7. 【RAG 检索增强·阶段6】私有知识模型没学过，硬问只会编。搭建"Markdown 拆分 → Embedding 向量化 → 向量检索 → 上下文增强"的完整 RAG 流水线，并在此基础上做了中文查询重写、status 元数据过滤（相似度阈值 + topK）和空结果兜底话术——回答可溯源、没检索到就明说；针对灵积 Embedding 单次 25 条的限制做了分批入库。

8. 【工具调用·阶段7】给模型配了 7 件工具（文件读写、联网搜索、网页抓取、资源下载、终端命令、PDF 生成、任务终止），全部按 @Tool / @ToolParam 规范开发、经 ToolCallbacks 统一注册，调用时机与参数由模型自主决策，跑通了"搜索 → 抓取 → 下载 → 写文件 → 生成 PDF"的端到端自动化任务。

9. 【手写 ReAct 智能体·阶段8】没有引入任何 Agent 框架，用 BaseAgent / ReActAgent / ToolCallAgent / HuiManus 四层抽象手写 ReAct 循环智能体：withProxyToolCalls(true) 从框架手里接管工具执行权、自维护消息列表形成"思考—行动—观察"闭环，TerminateTool 结束信号 + maxSteps 步数上限双保险防死循环；实测能自主完成"搜索地点 → 抓网页 → 下载图片 → 输出 PDF 约会计划"这类多步任务。

10. 【流式输出·阶段9】长回答干等 20 秒留不住人，全链路改成 SSE 流式输出（Flux 与 SseEmitter 双方案），ReAct 每干完一步就推一步；上线后定位到 nginx 默认 proxy_buffering 把流攒成整屏的问题，关缓冲后打字机效果完整还原。

11. 【接口服务化与跨域·阶段9】接口服务化后，前端 5173 调后端 8123 撞上浏览器同源策略，通过全局 CorsConfig（allowedOriginPatterns）放行跨域请求、支持携带凭据。

12. 【前端流式交互·阶段10】前端消费流式回答没有用 EventSource（感知不到流结束、无法中断），改用 fetch 手写 SSE 解析：按 `\n\n` 切事件、buffer 兜半包，配合 AbortController 做出"停止生成"按钮；Vue3 双页面分别呈现逐字输出与逐步播报两种节奏。

13. 【密钥安全·阶段11】API Key 从头到尾没进过仓库和镜像：公开配置进 git，真实密钥放 application-local.yml（.gitignore + .dockerignore 双重拦截），生产环境走环境变量注入——优先级高于包内一切配置，同一个 jar 插不同钥匙随处能跑。

14. 【容器化部署·阶段11】Dockerfile 采用多阶段构建（Maven 打包层 + JRE 运行层），Maven、源码全部留在构建层不带进成品，镜像从 1GB+ 降到几百 MB，Serverless 冷启动明显变快；再加 -XX:MaxRAMPercentage 让 JVM 堆自适应容器内存限额，最终部署到腾讯云开发（CloudBase）按量运行。

## 四、技能清单（放在项目经历上方）怎么写

按"熟练掌握 / 熟悉 / 了解"分层，**每一项都要能被简历条目佐证**：

- **熟练掌握**：Java 21、Spring Boot 3、Spring AI（ChatClient / Advisor / Tool / RAG / Memory）
- **熟悉**：ReAct Agent 原理、SSE 流式方案、MySQL、Docker 多阶段构建、Vue3 基础
- **了解**：LangChain4j、Ollama 本地模型、向量数据库（SimpleVectorStore / pgvector）、Kryo 序列化

## 五、常见错误（这么写会被面试官看穿）

1. **只堆技术名词**："使用了 Spring AI、RAG、Docker"——没有目的和效果，像背课文；
2. **写"参与了"**：参与xx项目开发——没有"你"做了什么，等于没写；
3. **效果注水**："性能提升 80%"（哪来的数据？）——数字要么可测，要么别编；
4. **写没吃透的东西**：写一行，就要准备好被追问三层（用 INTERVIEW.md 自检）；
5. **一条写三件事**：RAG + 工具调用 + 部署挤一条——拆开，每条一个闭环；
6. **动词软弱**："学习了、了解了、接触了"——换成"实现、搭建、定位、解决、优化"；
7. **句式全是一个模子**：条条"为了……，使用了……，达到了……"——一眼 AI 代笔。要素齐就行，开头换着来（见第三节的 14 条示范）。

## 六、最后一条建议

简历不是"做过什么"的清单，而是**你提前替面试官画好的考点地图**。每写一条，问自己三个问题：
1. 这条的**为什么**我讲得清吗？
2. 这条的**怎么做的**我画得出图吗？
3. 这条的**坑**我记得住吗？（踩坑故事是面试里最加分的部分）
